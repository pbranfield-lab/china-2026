### Three places the plan was deviated from, deliberately

Each was a defect found by testing, not a preference:

1. **The avatar crop.** The plan's box `(20, 300, 480, 760)` cut the top of
   Maisie's head and left an identifiable stranger prominent on the right. Read
   the source image, measured it (hair top ≈ y=340, chin ≈ y=700, face centre
   ≈ x=200, crowd starts x≈415) and used `(0, 310, 400, 710)` instead. The
   result was opened and checked before committing, per the project's own rule.
2. **The count-up's thousands grouping.** The plan's code ran every stat through
   `toLocaleString` with grouping always on. Tested against all 30 real stats:
   the two **year** stats (`1974` Xi'an, `1368` Great Wall) counted as `1,974`
   and then snapped to the ungrouped string on the final frame. Grouping is now
   inherited from the stat string itself. Verified: no drift on any of the 30.
3. **The jade enamel field was darkened.** The plan's own contrast step flagged
   `--mint` on `--jade` at **2.81:1** against a 4.5 requirement. The ramp is now
   `#226655 / #1B5949 / #123F34`, giving 5.53:1. `--jade` is used by nothing but
   that one field, so the change is contained to the jade fact tiles.

### ⚠️ A contrast finding the plan did not cover — Paul's call

The plan's contrast table measured each enamel gradient's **middle** stop. The
**lightest** stop of each gradient is what small text actually risks sitting on,
and there the numbers are worse:

| Field, lightest stop | `--mint` #8FE3DE | `--cream` #F5EDD8 |
|---|---|---|
| teal plate `#1D7C86` | **3.32** | 4.20 |
| coral field `#F2604C` | **2.17** | 2.74 |
| jade field (now `#226655`) | 4.58 ✓ | 5.80 ✓ |
| deep field `#14586B` | 5.39 ✓ | 6.82 ✓ |

Small text needs 4.5:1. So `.nav-card p`, `.family-card p`, `.bonus-feature p`
and the fact tiles' labels can fall below AA where they sit over the *top* of a
plate's gradient. The coral field cannot be fixed by lightening text at all —
even pure white only reaches 3.28 on `#F2604C`.

This was **not** fixed, because darkening the primary teal plate and the coral
field is a change to the approved design spec, not an implementation detail.
**Paul was asked on 2026-08-09 and chose to leave it and decide later**, on the
grounds that the affected text is secondary and mostly sits over the middle or
lower part of each plate, where the numbers do pass. It ships as-is at v2.0.0.

If it is revisited, the two workable options are:

- **(b)** Darken the teal and coral fields' light stops (roughly 0.75×), keeping
  the palette but flattening the gradients. This is the same treatment already
  applied to jade, and is the only one that fixes coral.
- **(c)** Lighten the secondary text to near-white on plates — fixes teal (white
  reaches 5.02 on `#1D7C86`), does **not** fix coral.

## The re-skin, in one paragraph

Muted lacquer-museum → Chinese cloisonné enamel. Saturated teal/gold/coral
grounds, chunky display type (Fraunces 900 / Outfit / Nunito, with Noto Serif SC
pinned onto every hanzi element because the Latin faces carry no CJK), and one
shared "enamel plate" material — gradient field, 1.5px gold wire, dark setting
ring, glaze highlight, lattice overlay — used by every raised surface on the
site. The "10 Mind-Blowing Facts" became teaser tiles that open an interactive
popout. `CLAUDE.md` describes all of it and is meant to stay true; this file
describes where the work got to.

### Gotchas the re-skin added

Carried forward on top of the existing list further down:

1. **Direct children of an enamel plate need `position:relative`.** The lattice
   overlay is an absolutely-positioned `::before`, so ordinary in-flow children —
   including photographs — paint underneath it. There is a grouped rule listing
   every plate class; extend it when you add one. `.location-close` is
   deliberately excluded so its `position:sticky` survives.
2. **The map's cream mat is `box-shadow` spread, never padding.** `#pinLayer`
   positions pins as percentages of `.map-inner`; padding there moves every pin
   off its landmark.
3. **The count-up needs its own reduced-motion guard.** It changes
   `textContent`, which the stylesheet's `prefers-reduced-motion` blanket cannot
   suppress — hence the `matchMedia` check in the facts IIFE.
4. **The count-up inherits thousands-grouping from the stat string.** Don't
   "simplify" it back to unconditional grouping; years count wrong.

### The TRIPS architecture

Three trips through **one shared set of pages**, made trip-aware by `?trip=<id>`.
No `?trip=` falls back to `TRIPS[0]`, so old links still work.

- `ofTrip(trip, items)` stamps `trip` onto a whole group.
- Photo id prefixes: `p*` Forbidden City, `x*` Xi'an, `g*` Great Wall.

**Adding a trip is pure data.** No HTML changes — the home-page chooser renders
from `TRIPS` automatically.

### Gotchas — don't regress these

1. **`PHOTOS.indexOf(p)` in the map popout is positional.** Those thumbnails
   index into the flat global `PHOTOS`. Don't point that path at a filtered
   copy. The gallery is safe because it looks up by `id`.
2. **`FAMILY[].file` already contains its folder** — use
   `Photographs/${person.file}`, never prepend a trip dir.
3. **`photoSrc(photo)` resolves from the photo's OWN `trip`**, not the current one.
4. **Nav highlight strips the query string from both sides** before comparing.
5. **The William box only renders when `loc.william` exists.** Neither Xi'an nor
   the Great Wall has any.
6. `?loc=` is validated against `TRIP_LOCATIONS` so a mismatched pair degrades.
7. **Per-trip pin CSS** is scoped via `:root[data-trip="..."]`. Xi'an and the
   Great Wall both shrink their pins; the Great Wall also hides the compass,
   because a side-on panorama has no north.
8. The facts section is `id="facts"` and stays `hidden` until the current trip
   has facts.
9. **`map.html` and `gallery.html` each hold their own copy of the modal
   markup.** Change one, change the other. `check.mjs` enforces it.
10. **`unloadVideo()` drops the `src`, it doesn't just pause.** A paused video
    that keeps its `src` carries on buffering and bleeds audio behind the
    closed overlay.
11. **Every internal link is rewritten to carry `?trip=`, not just the nav.**
    The rewrite **skips links that already contain `trip=`** — that is what
    stops the home-page chooser cards all being rewritten to the same trip.
    Don't remove that check.
12. **Hash is split off before the query** when rewriting hrefs, or
    `story.html#facts` becomes `story.html#facts?trip=…`.
13. **The `#facts` landing jump re-asserts position for ~1.2s** and releases on
    `wheel`/`keydown`/`pointerdown`/`touchstart`. It's not over-engineering: the
    section is revealed by script, and the big CJK webfonts land after load and
    reflow the long intro by hundreds of pixels, so a single jump lands wrong.
    `pointerdown` is in the list because a scrollbar drag fires none of the
    others.

⚠️ **Browser-automation scroll checks are unreliable here.** Programmatic
scrolling is suppressed in that context and the screenshot tool resizes the
viewport (which resets scroll). Read `window.scrollY` after a real page load, or
check by hand.

## Photo curation workflow

1. **Triage.** Contact sheets are far cheaper than opening 82 images
   individually: scale to thumbs, then `ffmpeg -start_number N -i "%03d.jpg"
   -vf "tile=4x3:margin=8:padding=6"`. **Use
   `scale=W:H:force_original_aspect_ratio=decrease` + `pad`** — plain
   `scale=W:-2` then `pad` fails on portrait shots.
   **`drawtext` segfaults on this machine** (no fontconfig) — number tiles by
   grid position instead.
2. **Then open every finalist properly with Read** before writing about it.
   Contact sheets are good enough to group and drop, not to caption. The "ice
   cream" that was a fan was legible at full size and not at thumbnail size.
3. **Propose a rename + grouping table and wait for explicit confirmation**
   before touching disk.
4. **Resize:** `-vf "scale='if(gt(iw,ih),1400,-2)':'if(gt(iw,ih),-2,1400)'" -q:v 4`
   (`-q:v 6` for anything still over ~250 KB).
5. **Deleting raws needs an explicit OK each time.**

### Video

Phone video is **HEVC** — re-encode to H.264 for browser support, not just size.
204 MB → 17 MB at `scale=960:-2 -crf 30 -preset slow -c:a aac -b:a 80k
-movflags +faststart`. Add `type:"video"` to the `PHOTOS` entry.
