## ⚠️ Next up, by Paul's request: a full site-navigation audit

Paul closed the session on this (screenshot: play.html showing a
**"The Forbidden City ⇄" nav chip on the Games page**). The problem class:

- `CURRENT_TRIP` falls back to `TRIPS[0]` when there's no `?trip=`, and the
  contextual nav (site.js ~line 110) injects the trip chip on **every**
  non-index page — including the trip-agnostic ones (family, journey, play).
  The Games page therefore claims you're "in" the Forbidden City.
- Worse, the trip-scoped nav links (Story / Facts / Map / Gallery) clicked
  from an agnostic page silently carry `?trip=forbidden-city` — the exact
  silent-default landing the index page's link-hiding was built to prevent.
- Whether a trip was **explicitly chosen** is detectable:
  `new URLSearchParams(location.search).has("trip")`. That's the lever the
  current code never uses.

Audit scope to consider (decide with Paul, don't assume):
1. Chip behaviour on agnostic pages with no explicit trip — hide it, or turn
   it into a "Pick a trip" prompt instead of naming the default.
2. Trip-scoped nav links from agnostic pages without an explicit trip —
   route via the chooser (index) rather than defaulting, or prompt.
3. Consider remembering the last explicitly chosen trip in `store`
   (key would join the documented map in site.js) so context follows the
   reader instead of resetting to the default.
4. General pass: nav order/labels, current-page highlight on agnostic pages,
   mobile menu with 7 links, where the Play/Journey CTAs sit.

Hard constraints while touching any of this: the nav header must stay
byte-identical across all 7 pages (check 7) — per-page behaviour is JS only;
the `TRIPS[0]` fallback must keep old deep links working; the `?trip=`
rewrite whitelist and its param-discarding are documented in CLAUDE.md.

## Closing out a session

1. Rewrite this file: current state, what's next, open decisions. **Keep it
   under ~5 KB.** Don't duplicate `CLAUDE.md`, `docs/authoring.md` or memory.
2. `git mv docs/HANDOFF-<old>.md docs/HANDOFF-YYYY-MM-DD-HHMM.md`.
3. Update `CLAUDE.md` if the *architecture* changed.
4. Bump `SITE_VERSION` in `assets/data.js` if content or behaviour changed —
   and re-stamp the `?v=` asset links to match.
5. Commit and push — pushing `master` publishes. Check `git remote -v` says
   `china-2026` first.
